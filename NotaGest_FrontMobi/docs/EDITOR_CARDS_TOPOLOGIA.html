Guia Resumido: Entrada (DNAT), Tráfego Interno (Guest Network) e Saída para Nuvem (SNAT)

  • Navegador Web (Desktop / Mobile)

  • 1. Usuário digita a URL ou abre o App
  • 2. Pacotes trafegam pela Internet pública
  • 3. Destino: IP PÚBLICO da CloudStack
• PORTAS DE ENTRADA:
  • -> Porta 4000: Interface Web (Next.js)
  • -> Porta 5000: API Backend (Node.js)
• ISOLAMENTO DE SEGURANÇA:
  • O usuário externo NUNCA enxerga os IPs privados internos das VMs!
  • Toda comunicação passa pelo VR.
1. Acesso Externo [Portas 4000 e 5000]
APACHE CLOUDSTACK — AMBIENTE ISOLADO (GUEST NETWORK PRIVADA)
VLAN/VxLAN Privada: As VMs comunicam-se entre si | Borda protegida pelo Virtual Router
GATEWAY DE BORDA VIRTUAL ROUTER (VR)
Debian VR — Gateway e Roteador de Borda da CloudStack
  • INTERFACE WAN: IP Público (recebe clientes e faz saída SNAT)
  • INTERFACE LAN: Gateway 192.168.1.1 (conecta às Guest VMs)
• PAPEL 1 [ENTRADA - DNAT / PORT FORWARDING]:
  • -> Porta pública :4000 encaminhada para a VM Web (192.168.1.10:4000)
  • -> Porta pública :5000 encaminhada para a VM Backend (192.168.1.20:5000)
• PAPEL 2 [SAÍDA - SNAT / SOURCE NAT]:
  • -> Quando o Backend solicita Atlas ou Gemini, o VR traduz o IP privado da VM para o IP Público oficial para navegar na Internet
DNAT -> Web [TCP 4000] 3. Envia ao Gateway [Roteamento SNAT] DNAT -> Backend [TCP 5000]

RESUMO OPERACIONAL DOS 3 FLUXOS DE REDE:

1. FLUXO DE ENTRADA (Inbound - Azul/Ciano): O usuário acessa o IP Público do Virtual Router -> O VR realiza Port Forwarding (DNAT) direcionando a porta 4000 para o Web e a porta 5000 para a API.

2. FLUXO INTERNO (Local - Verde): O Frontend Web se comunica diretamente com o Servidor Backend pela Guest Network privada isolada (http://192.168.1.20:5000), com velocidade local e zero consumo de banda WAN.

3. FLUXO DE SAÍDA (Outbound - Laranja): O Servidor Backend precisa acessar o MongoDB Atlas (:27017) ou Google Gemini (:443) -> Envia ao VR -> O VR mascara via Source NAT (SNAT) com o IP Público e entrega aos serviços na Internet.
